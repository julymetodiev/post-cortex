# Migration waves (history)

The waves that built the system, kept as a record; not the specification. New work is on the `pcx` board.

Status: target architecture, agreed 2026-10-21. The code is moved to it in waves (section 10);
until a wave lands, the current code is described in the inventory it replaces.

Each wave ends green: all CI jobs, the micro-benchmarks against the baseline, and for waves that
touch retrieval, the fast + accurate LoCoMo run (about 30 min). Green checks are not enough: before a wave is
committed, its diff is reviewed against the rules in section 2 (type boundaries, visibility,
duplication), and every rule is enforced by a CI check from the wave that introduces it. No wave changes the export format,
the on-disk format or the wire schemas except where it says so.

Every wave leaves the files it owns within the 500-line limit (rule 6); a file that a later wave rewrites or removes (transport handlers before W5, `StorageActor` before W3) only gets its call sites updated and stays on the allowlist until that wave. The size check runs in
CI from W1 with an allowlist of the files still over the limit; each wave removes its files from
the allowlist, and the allowlist is empty by the end of W7.
